# Reels Studio

Телеграм-бот и мини-апп: эксперт загружает сырое видео — забирает готовый
вертикальный ролик с титрами, врезками и звуком.

Оплата разовыми пакетами через Lava.top, никаких подписок.

---

## Как это устроено

```
Telegram  ──►  бот (grammy)         вход, уведомления, готовые ролики
               мини-апп (miniapp/)  загрузка, шаблоны, редактор с таймлайном
                     │
                     ▼
               API (fastify)        авторизация по подписи Telegram,
                     │              приём файлов, вебхук кассы
                     ▼
               очередь (Postgres)   задачи на рендер
                     │
                     ▼
               воркер               разбор дорожки → разметка → Remotion → mp4
```

### Папки

| Путь | Что внутри |
|---|---|
| `server/` | бэкенд: API, бот, очередь, платежи |
| `server/pipeline/engine.js` | мост к монтажному движку |
| `engine/` | сам движок монтажа (Python + Remotion) |
| `src/` | наши компоненты Remotion — остались от первой версии |
| `miniapp/` | интерфейс мини-аппа (статика) |
| `migrations/` | схема базы, применяется сама при старте |
| `public/` | шрифты, звуки, исходное видео для студии |

### Разделение труда

Система собрана из двух половин, и это главное, что нужно про неё понимать.

**`engine/` решает, каким будет ролик.** Распознаёт речь, режет паузы и слова-
паразиты, размечает смысл фраз (`HOOK`, `POINT`, `CONTRAST`, `CTA`), считает
вёрстку субтитров по настоящим метрикам шрифта, следит за слепыми зонами
площадок и лицом в кадре, мастерит звук до −14 LUFS, зовёт Remotion и в конце
сам выставляет себе оценку качества.

**`server/` решает, кому и когда.** Очередь, оплата, лимиты, хранение,
доставка ссылкой, уведомления в бот.

Между ними один вызов: `runEngine()` в [engine.js](server/pipeline/engine.js).
Движок получает временный `config.json` со своими путями и отдаёт готовый
файл плюс `quality_report.json`. Наш шаблон монтажа переводится в стилевой
профиль движка (`expose` → `REELS_DENSE`, `warmup` → `PODCAST`).

Речь распознаётся одним и тем же провайдером в обеих половинах: ключ
`SPEECH_API_KEY` вписывается один раз. Без ключа движок работает локальной
моделью `faster-whisper` — бесплатно, но медленно и с полутора гигабайтами
памяти на ролик.

### Что делает мини-апп

Интерфейс работает на живом API, никаких заглушек:

| Экран | Откуда данные |
|---|---|
| Профиль | `POST /api/me` — имя, остаток пакета, срок, статистика, реф-ссылка |
| Пакеты | `GET /api/meta` + `POST /api/pay` — ссылка на кассу |
| Создать | `POST /api/videos/create` — загрузка с прогрессом и ключом `X-Request-Id` |
| Ролики | `POST /api/videos` раз в 3 секунды, пока в очереди что-то есть |
| Готовый ролик | `GET /dl/<токен>` — та же ссылка, что бот шлёт в чат |
| Правка | `POST /api/videos/:id/rebuild` с метками таймлайна |

Длительность проверяется дважды: в браузере через метаданные файла — чтобы
не тянуть сотню мегабайт впустую, и на сервере через `ffprobe` — до списания
кредита, потому что клиенту верить нельзя.

## Локальный запуск

Нужны Node 22+, ffmpeg и Postgres.

```bash
git clone <твой-репозиторий> reels-studio
cd reels-studio
npm install
cp .env.example .env      # заполни BOT_TOKEN, DATABASE_URL, SPEECH_API_KEY
npm run dev
```

Postgres на маке ставится одной командой:

```bash
brew install postgresql@16 && brew services start postgresql@16 && createdb reels
```

Тогда в `.env` строка подключения будет такой:

```
DATABASE_URL=postgresql://ТВОЙ_ЮЗЕР@localhost:5432/reels
```

Миграции применятся сами при первом старте. `.env` подхватывается
автоматически — отдельный `dotenv` не нужен.

Мини-апп внутри Telegram работает только по **https**, поэтому локально
подними туннель и укажи его адрес в `PUBLIC_URL`:

```bash
cloudflared tunnel --url http://localhost:3000
```

## Railway

### 1. Проект и база

1. **New Project → Deploy from GitHub repo** → выбери репозиторий.
2. В проекте: **New → Database → Add PostgreSQL**.

### 2. Диск для видео

Без него загруженные файлы исчезнут при первом же редеплое.

**Service → Settings → Volumes → Add Volume**, точка монтирования `/data`.

### 3. Переменные

**Service → Variables → Raw Editor**, вставь блок целиком и заполни пустые:

```
BOT_TOKEN=токен_от_BotFather
BOT_USERNAME=имя_бота_без_собаки
DATABASE_URL=${{Postgres.DATABASE_URL}}
STORAGE_DIR=/data
ADMIN_IDS=твой_telegram_id
NODE_ENV=production
BOT_MODE=polling
PACKAGE_DAYS=90
REFERRAL_BONUS=10
RENDER_CONCURRENCY=1
PREVIEW_COST=0.3
PREVIEW_SCALE=0.45
MAX_UPLOAD_MB=2048
WEB_ENABLED=1
WORKER_ENABLED=1
```

`${{Postgres.DATABASE_URL}}` — это ссылка на плагин базы, Railway подставит
строку подключения сам. Писать её руками не надо.

`PUBLIC_URL` не задавай: он соберётся из домена Railway автоматически.
Понадобится только если повесишь свой домен.

### 4. Домен

**Settings → Networking → Generate Domain**. Полученный адрес пригодится
для кассы и для кнопки в боте.

### 5. Проверка

После деплоя открой в браузере:

```
https://твой-домен.up.railway.app/api/health
```

Ответ `{"ok":true,"lava":false}` означает, что сервер поднялся, база
подключена, касса пока в тестовом режиме.

Дальше напиши боту `/start` — должна прийти кнопка «Открыть студию».

## Подключение кассы Lava.top

1. Заведи **три товара** в кабинете — по одному на пакет.
   Цены: 4 990, 7 490, 12 990 ₽.
2. Скопируй их `offerId` в `LAVA_OFFER_START`, `LAVA_OFFER_PRO`,
   `LAVA_OFFER_STUDIO`.
3. Укажи адрес вебхука:
   `https://твой-домен.up.railway.app/webhook/lava`
4. Положи ключ в `LAVA_API_KEY`, секрет вебхука — в `LAVA_WEBHOOK_SECRET`.

**Пока ключа нет** оплата работает в тестовом режиме: кнопка ведёт на
страницу-заглушку, которая начисляет ролики без списания денег. Удобно,
чтобы проверить весь путь клиента до подключения кассы.

### Что придётся поправить руками

Точная форма запроса на создание счёта и формат вебхука зависят от версии
API кассы. Я не могу их угадать, поэтому собрал всё специфичное для Lava
в двух функциях в [server/lava.js](server/lava.js):

- `callLavaInvoice` — тело запроса, должна вернуть `{invoiceId, payUrl}`
- `readWebhook` — разбор вебхука, должна вернуть `{orderId, invoiceId, paid}`

Сверь их с документацией в своём кабинете. Остальной код от формата не
зависит: начисление, защита от двойного вебхука и уведомления работают
поверх этих двух функций.

## Команды бота

**Для клиента**

| Команда | Что делает |
|---|---|
| `/start` | Приветствие и кнопка входа в студию |
| `/balance` | Сколько роликов осталось и до какого числа |
| `/help` | Как пользоваться |

**Для администратора**

Работают только у тех, чей Telegram id указан в `ADMIN_IDS`. Для всех
остальных бот на эти команды молча не отвечает — чужой не должен даже
узнать, что они существуют.

| Команда | Что делает |
|---|---|
| `/admin` | Список админских команд |
| `/give @ник 30` | Начислить ролики. Клиенту придёт уведомление |
| `/take @ник 10` | Списать ролики |
| `/who @ник` | Карточка клиента: баланс, ролики, оплаты, движения |
| `/stats` | Сводка: клиенты, ролики, выручка, себестоимость |
| `/queue` | Что рендерится прямо сейчас и что ждёт |

Вместо `@ника` везде можно указать номер телеграма — удобно, когда у
клиента ника нет.

Выдать доступ бесплатно: `/give @ник 30` — начислит 30 роликов и продлит
пакет на 90 дней. Каждое такое начисление попадает в историю движений,
поэтому потом видно, кому и сколько выдал вручную.

## Хранение и доставка

Диск — единственная статья расходов, которая растёт сама по себе.
Поэтому файлы живут ограниченный срок:

| Файл | Сколько лежит | Зачем столько |
|---|---|---|
| Исходник клиента | `SOURCE_KEEP_DAYS`, по умолчанию 2 дня | окно на пересборку с правками |
| Готовый ролик | `OUTPUT_KEEP_DAYS`, по умолчанию 30 дней | клиент забирает его в первые дни |
| Обложка | не удаляется | 50 КБ, но без неё библиотека выглядит пустой |

Уборщик ходит по диску раз в час (`STORAGE_SWEEP_MIN`). Когда срок ролика
истекает, файл удаляется, а карточка остаётся со статусом `expired` —
клиент видит, что ролик был, и понимает, почему его больше нет.

Поставь `SOURCE_KEEP_DAYS=0`, если хочешь удалять исходники сразу после
монтажа. Правки после этого станут невозможны: пересобирать не из чего.

**Готовый ролик уходит ссылкой, а не файлом.** Bot API не пропускает
отправку больше 50 МБ, а минутный рилс весит больше. Поэтому бот присылает
кнопку «Скачать» на `/dl/<токен>` — ссылка отдаёт файл любого размера,
поддерживает перемотку и умирает вместе с файлом по истечении срока.

## Стоимость одного ролика

| Статья | Сколько |
|---|---|
| Расшифровка | ~$0.005 |
| Рендер | $0.02–0.20 |
| Хранилище и трафик | ~$0.005 |
| **Итого** | **примерно 20 ₽** |

Отсюда маржа: 88% на «Старте», 84% на «Про», 54% на «Студии».
Точка нуля — 250 роликов на клиента, поэтому лимиты в пакетах обязательны.

Замеры на 50-секундном ролике, Apple M2, 8 ядер:

| Этап | Время |
|---|---|
| Распознавание через API (`groq`) | ~3 с |
| Распознавание локальной моделью (`faster-whisper medium`) | ~100 с |
| Разбор, речевой монтаж, разметка, вёрстка | ~7 с |
| Рендер | 275 с |
| **Полный цикл с API-распознаванием** | **около 5 минут** |

Локальная модель бесплатна, но держит полтора гигабайта памяти и добавляет
полторы минуты процессорного времени. На сервере, где рендер и так занимает
все ядра, ключ к API окупается сразу — поэтому `SPEECH_API_KEY` стоит задать
даже ради экономии, а не только ради качества.

Каждый смонтированный ролик пишет свои цифры в базу: время монтажа, размеры
входа и выхода, провайдер речи, сколько секунд речи срезано. Сводка за 30 дней —
команда `/stats` в боте. Одна строка на ролик уходит и в лог контейнера:

```
ролик 42 · готов · 50.0с · речь groq · срезано 0.4с речи · монтаж 289.0с · качество 0.57 · вход 22.9МБ · выход 42.7МБ
```

Оценку качества движок ставит себе сам по восьми измерениям (содержание,
монтаж, типографика, визуал, врезки, камера, звук, техника) и пишет их
в `quality_report.json`. Низкая оценка — повод посмотреть его же
рекомендации в том же файле, они на русском и по делу.

## Что работает и что нет

**Работает:** авторизация по подписи Telegram, мини-апп на живых данных,
загрузка исходников с прогрессом, лимит 3 минуты, очередь с повторами
и возвратом кредита при сбое, защита от двойного запуска, разбор дорожки,
шаблонная разметка, рендер, выдача ролика ссылкой, автоочистка диска,
замеры себестоимости, пакеты и реферальная программа, тестовый режим оплаты.

**Ждёт тебя:**

- **Ключ распознавания** — впиши `SPEECH_API_KEY` в `.env` или в переменные
  Railway. На сервере он обязателен: локальная модель туда не ставится,
  и без ключа монтаж остановится с внятной ошибкой. Ключ берётся на
  console.groq.com/keys, стоит копейки за ролик.
- **Поля API Lava** — две функции в `lava.js`, см. выше.
- **Модельная разметка** — включится сама, когда появится `ANTHROPIC_API_KEY`.

Полный цикл прогоняется одной командой:

```bash
npm run e2e
```

32 проверки на настоящем Postgres: загрузка → распознавание → монтаж →
рендер → выдача ссылки, плюс лимит длительности, защита от дублей, метрики,
сроки хранения. Скрипт поднимает API и воркер без телеграма — initData
подписывается тем же `BOT_TOKEN`. Занимает несколько минут: внутри
настоящий рендер. Тестовый пользователь чистится в начале прогона.
